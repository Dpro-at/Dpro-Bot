# Capture,synthesis and assets

## Record

Identify speakers,room/remote setup,microphones,interfaces,tracks and actual capture tool. Use a short authorized test for signal,noise,clipping,monitoring and backup recording where supported. A selected input is not proof sound was captured. Do not change participant equipment or install drivers without authority.

Record format,sample rate,bit depth,channels,sync/clock assumptions and file naming. Retain original takes and note dropouts,overlap,pronunciation corrections and room tone. Separate tracks help editing but do not guarantee isolation. Keep raw/private material in approved storage and retention scope.

## Synthesize

When requested and authorized,select supported voices/models with actual usage rights. Do not clone real voices without required consent. Define speaker labels,pronunciation,delivery and segment boundaries. Test a representative segment before a costly run. Check current provider capabilities/pricing rather than assuming fixed speaker limits or model names.

Track script/version,inputs,tool/model/settings,cost boundary and actual output/errors. A job ID is not usable audio. Inspect omissions,repetition,mispronunciation,speaker swaps and unintended content before assembly. Reconcile partial generation before retry to avoid duplicate cost/material.

## Other assets

Inventory music,ambience,archive clips,artwork and transcripts with file identity,source,license,usage scope and credits. Search results or streaming access do not establish reuse rights. Keep consent/private references out of public/general packages.

If capture or synthesis cannot run,deliver complete input/asset requirements and production notes. No dependency/model installation,service activation or paid API follows from loading this reference.

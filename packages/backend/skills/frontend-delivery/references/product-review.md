# Product and visual review

## Structure follows the work

Identify the main object and action. Keep context that supports the action visible; move unrelated configuration into the product's established settings surface. For selected-object workflows, a quiet list and an adjacent editor often reduce repeated navigation. A focused canvas may need more space and a collapsible inspector.

Do not apply a desktop layout to a landing page or a marketing hero to a desktop settings form. In Girru, the current section owns the shared sidebar. A second sidebar that repeats the same places makes the product harder to understand.

## Deliberate visual decisions

Use typography, spacing, contrast and alignment to express hierarchy. A new design should have a reason for its choices in the subject and audience. An existing product should retain its familiar tokens and interaction patterns unless the requested change includes a new direction.

Give important actions a clear visual place. Repeated filled buttons compete with one another. Counts should help interpret the current work; they should not become decorative statistics. Use icons consistently and give icon-only commands accessible names.

## Content is part of the interface

Name controls by what the person does. A settings form can expose a technical value when it helps an actual decision; it should not display internal identifiers merely because they exist. Put diagnostics in the appropriate secondary surface.

Empty states distinguish no records, no matches, missing access and unavailable service. Error text identifies the failed operation and recovery. Do not claim that a save failed definitively if the request outcome is unknown.

## Responsive composition

Define priority: primary work area, necessary navigation and optional inspector. Collapse the least necessary pane first. Test long text and minimum widths before adding truncation. At narrow sizes provide a clear route back to the list or navigation.

Review the actual rendered result in both themes. Check spacing, clipped content, sticky elements, focus and footer overlap. A DOM width check is useful evidence, but visual inspection is still needed to judge hierarchy and readability.

## Scope and restraint

Remove a control when its purpose is already covered elsewhere, but preserve a reachable path for an existing feature. Do not silently delete capabilities to make a screenshot calmer. If a feature moves into a disclosure or menu, record where it went and test its route.

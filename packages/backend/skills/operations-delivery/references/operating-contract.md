# Operating contract and record identity

Identify the organization/team,requested decision,system/process/project,owner,time horizon and actual deliverable. Locate the current inventory ledger,process repository or project tracker before creating another. Record source snapshot/version,time zone,units,currency and update authority. A stale extract can support historical analysis without representing current state.

Use stable item/location/task/process identifiers and define joins before merging. Similar names are not proof of identical objects. Distinguish actual,committed,proposed,estimated,blocked,failed and unknown states. A forecast date is not an agreed deadline;an assigned-looking cell is not confirmation that the person accepted work.

Inspect data quality proportionately:duplicates,missing fields,negative/invalid values,unit conversions,status transitions and concurrent updates. Keep source records intact and maintain correction provenance. Do not overwrite unrelated fields or reconcile conflicting ledgers by choosing whichever looks simpler.

Bound access and disclosure to the decision. Useful artifacts can use aggregate/sanitized evidence and controlled references. Actual stock adjustments,purchase orders,task assignments,schedule changes,messages and publication require applicable authority. Prepare a concrete reviewable result before leaving a required decision pending.

When current state cannot be observed,deliver the useful scoped analysis or proposed workflow and state exactly what must be rechecked before action. Avoid inventing live system health or promising that the plan has been adopted.

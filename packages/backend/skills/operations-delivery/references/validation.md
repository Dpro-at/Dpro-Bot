# Validation and handoff

Choose checks that resolve the current decision uncertainty. For data verify source/as-of,units,identity,aggregation and decisive arithmetic. For procedures check realistic inputs,decision paths,exceptions,handoff outputs and ownership. For projects compare status/forecast with baseline,dependencies and actual acceptance evidence.

Use a bounded representative example or walkthrough where appropriate and available. Label hypothetical examples and simulations clearly. A calculation confirms declared arithmetic,not true demand,inventory correctness,supplier reliability or process adoption. A source document review is not live execution. Do not install systems or query private accounts merely to claim a check ran.

Keep proposed actions and actual effects distinct. Before an authorized mutation bind current object/version,action scope and relevant owner approval,then read back actual result. Reconcile timeout/partial outcomes before retry to avoid duplicate orders,tasks or notifications. Preserve unrelated data and the original baseline.

Deliver concrete artifacts,source/method,checks and results,material limitations and next responsible decision. Keep private records and credentials outside reusable settings/archives. Actual model-task quality,domain judgment and live operational acceptance remain separate from package parsing/discovery and library-preservation trials.

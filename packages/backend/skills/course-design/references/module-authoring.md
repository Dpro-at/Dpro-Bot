# Module authoring

Write for the actual learner and modality. A self-paced module needs sufficient explanation, resources and feedback to proceed independently. A facilitated session needs usable instructions, timing assumptions and facilitator guidance. Do not confuse an instructor's topic outline with learner-ready content.

## Build the learning path

Open with the meaningful task and required starting point. Explain the relevant concept or process in an accessible sequence with examples that match the outcome. Make relationships and transitions clear without repeating the same objective paragraph on every page. Define necessary terminology when it first matters.

Provide a worked or contrasting example when it reveals a non-obvious decision. Verify its correctness and source rights. Distinguish a synthetic example from a real case; do not invent named participants or operational results. Then give the learner a manageable attempt with clear inputs and expected output.

Use headings, lists, tables, diagrams or media where they improve comprehension. Avoid decorative media that competes with the task or requires an unavailable service. Describe assets still needed rather than presenting placeholders as complete. For a technical lesson, ensure code/data examples match the intended runtime and label actual execution evidence.

## Support and feedback

Add hints, error explanations and a route back to the relevant material where useful. Provide an independent transfer opportunity rather than revealing the entire answer before every attempt. Make facilitator-only answers and learner-facing material distinct. An AI-generated explanation still needs substantive subject review when accuracy matters.

For mixed starting points, identify optional foundations and more challenging extensions without making the essential path confusing. Choose length and segmentation around meaningful tasks and learner control, not a universal page/word/time cap. Estimate effort for doing the work as well as consuming the content.

## Usability and access

Use readable structure, meaningful link labels, descriptive alternatives for necessary visuals and usable table headers. Plan captions/transcripts and keyboard interaction for media/platform features. Preserve the instructional purpose when offering an alternative format; an inaccessible drag interaction may need an equivalent reasoning task rather than a static screenshot.

Check language/register and cultural assumptions. Avoid requiring unnecessary personal disclosure for practice. Use fictional cases and synthetic data when the learning objective does not require real records. Follow the institution's actual accessibility and learner-support process; do not fabricate contact details or certification statements.

## Readback

Review the exported or platform-previewed artifact, not only the source text. Confirm links, asset dependencies, answer separation and navigation. A Markdown document can be complete as a design deliverable while LMS interaction/tracking remains untested. State the exact delivered form and missing target acceptance.

# Outcomes and scope

Name the course's practical purpose and audience before selecting content. Use supplied performance examples, task observations, existing assessments or learner work where authorized. Keep evidence and assumptions separate. A stakeholder request for a course is useful context but not proof that instruction solves the underlying problem.

## Define observable outcomes

Write what the learner will do, under which relevant conditions and what acceptable performance looks like. Include constraints only when they matter to the real task. An objective such as knowing a topic needs a more observable interpretation; do not merely swap in a fashionable action verb while leaving the task vague.

Distinguish factual recall, conceptual interpretation, procedural execution and strategic judgment where that distinction changes practice or assessment. A taxonomy can help discussion, but context and actual work determine the demand. Avoid claiming a universal cognitive level from the word analyze, explain or design alone.

Choose stable local objective IDs so activities, assessments and later revisions can refer to the same intended outcome. Keep each outcome meaningful rather than splitting it into many trivial checklist items. Separate required outcomes from optional enrichment, orientation and administrative information.

## Scope and sequencing

Map the essential task dependencies and learner starting point. Some learners benefit from a worked example, some from an initial challenge with targeted support. Treat those as design choices to test, not fixed rules about every novice or expert. Provide a route for learners with different prior knowledge when the task warrants it.

Estimate time for reading/listening, practice, feedback, revision and assessment, not only presentation length. State assumptions about available equipment, internet, language and facilitator support. If the scope exceeds the budget, explain the tradeoff and propose a smaller coherent outcome rather than compressing every activity into an implausible timetable.

## Revision boundary

For an existing course, identify which materials already serve the outcomes and which specific gaps need repair. Preserve stable IDs, valid links, approved policy and useful learner context. Do not overwrite the original course merely because a new template is available. For new work, distinguish a full course from a prototype/sample module in the delivery record.

## Content authority

Identify domain experts and trustworthy references for factual or procedural claims. Do not invent research citations, institutional standards or named policies. Where current law, safety practice, exam specification or technical API is central, use the applicable authoritative current source within the user's permission scope. A course structure can be ready while domain approval remains open.
